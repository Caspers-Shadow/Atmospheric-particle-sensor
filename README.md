# Atmospheric Monitoring System (Raspberry Pi 5 + Enviro+ + PMS5003)

Low-cost atmospheric sensing platform built for a stratospheric balloon
payload (~30 km AMSL), per the project PRD. Collects environmental data,
particulate matter, and relative gas trend indices, displays them on the
onboard LCD, logs them locally, and uploads them to ThingSpeak.

## Files

```
project/
|-- readings.py                    # sensor acquisition + LCD + ThingSpeak upload loop
|-- analyse.py                     # CSV import, cleaning, stats, gas trend, experiment extraction
|-- requirements.txt
|-- thingspeak_data.csv            # generated at runtime by readings.py
|-- cleaned_thingspeak_data.csv    # generated by analyse.py
|-- experiment.csv                 # generated by analyse.py (only with --start/--end)
|-- gas_report.csv                 # generated by analyse.py
```

## Hardware

- Raspberry Pi 5
- Pimoroni Enviro+ (BME280, LTR559, MICS6814, ST7735 LCD)
- PMS5003 particulate matter sensor (UART)

## Setup on the Raspberry Pi 5

1. Enable I2C, SPI, and the serial UART in `raspi-config` (UART login
   shell must be disabled, UART hardware enabled — required for PMS5003).
2. Install system packages needed by the Pimoroni libraries (I2C/SPI
   dev tools, `python3-dev`, `libjpeg-dev` for Pillow, etc.).
3. Install Python dependencies:

   ```bash
   pip install -r requirements.txt --break-system-packages
   ```

4. Set your ThingSpeak Write API Key as an environment variable (don't
   hardcode it):

   ```bash
   export THINGSPEAK_WRITE_API_KEY="your_key_here"
   ```

5. Optional: calibrate clean-air gas baselines before flight and export
   them, e.g.:

   ```bash
   export GAS_BASELINE_OXIDISING=21500
   export GAS_BASELINE_REDUCING=185000
   export GAS_BASELINE_NH3=190000
   ```

## Running the acquisition system

```bash
python3 readings.py
```

This will:
- read all sensors on a < 1 second refresh cycle,
- print the console SENSOR READINGS and GAS REPORT blocks every cycle,
- append each reading to `thingspeak_data.csv`,
- update the LCD (page advances on proximity trigger),
- upload to ThingSpeak every 20 seconds,
- log all exceptions to `atmo_system.log` and keep running through
  PMS5003 timeouts or ThingSpeak upload failures.

Stop with `Ctrl+C` for a clean shutdown.

## Running the analysis

After a flight (or a test run), analyse either the local CSV or a
ThingSpeak channel export:

```bash
python3 analyse.py --input thingspeak_data.csv
```

To isolate a specific experiment window (times in Africa/Johannesburg
local time):

```bash
python3 analyse.py --input thingspeak_data.csv \
    --start "2026-07-01 08:00:00" --end "2026-07-01 10:00:00"
```

This produces `cleaned_thingspeak_data.csv`, `gas_report.csv`, prints
summary statistics (count/mean/min/max) to the console, and — when a
window is given — `experiment.csv`.

## Important limitations (per PRD)

This system does **not** provide laboratory-grade gas identification,
individual molecule counting, or absolute ppm-accurate concentrations,
particularly at stratospheric altitude where the MICS6814 has not been
characterised. Gas readings are relative 0–100 indices derived from raw
sensor resistance against a ground-calibrated baseline, intended for
trend analysis and STEM education only. The NO2/CO/H2/CH4/NH3/C3H8/C4H10
/ethanol "sub-indices" in the console gas report share values within
the same MICS6814 sensing element (oxidising, reducing, NH3), since the
sensor cannot distinguish between gases on the same element — this is a
hardware limitation, not a software bug.
